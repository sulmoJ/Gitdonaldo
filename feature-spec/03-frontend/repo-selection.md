# 대상 레포 지정과 새로고침

근거: `public/app.js:13-22`, `public/app.js:257-261`, `server.js:11`, `server.js:141`

## 지정 방법과 우선순위

| 우선순위 | 방법 | 범위 | 유지 |
|---|---|---|---|
| 1 | 상단 입력창에 경로 입력 후 Enter | 현재 탭 | 새로고침(F5)하면 사라짐 |
| 2 | 페이지 URL 쿼리 `/?repo=/path/to/repo` | 해당 URL | URL을 북마크·공유 가능 |
| 3 | 서버 환경변수 `REPO` | 서버 전체 기본값 | 서버 재시작 전까지 |
| 4 | 서버 실행 디렉터리 | 서버 전체 기본값 | — |

1·2는 클라이언트가 API 호출에 `repo` 쿼리를 붙여 서버에 넘기고, 3·4는 쿼리가 없을 때 서버가 고른다.

## 경로 입력창 `#repoInput`

- placeholder: `repo 경로 입력 후 Enter`
- Enter: 앞뒤 공백을 잘라 `state.repoPath`에 넣고 `load()` 실행
- 빈 값으로 Enter: `state.repoPath`가 빈 문자열이 되어 URL `?repo=` 또는 서버 기본값으로 돌아간다.
- 로딩에 성공하면 입력창 값을 서버가 알려준 **레포 최상위 경로**로 바꾼다. 하위 디렉터리를 입력해도 최상위 경로로 정규화돼 보인다.
- 입력한 경로는 브라우저 URL에 반영하지 않는다.

## 새로고침 버튼 `#refreshBtn` (⟳)

현재 지정된 레포로 `load()`를 다시 실행한다. 레포 정보, ref, 커밋, 상태를 모두 다시 받는다. 저장소에서 커밋하거나 브랜치를 바꾼 뒤 화면을 갱신하는 용도다. 자동 갱신(폴링·파일 감시)은 없다.

## 잘못된 경로

서버가 400 `not a git repo: <경로>`를 돌려주고, 상단 레포 정보 자리에 빨간 글씨로 표시된다. 커밋 목록과 그래프는 비워진다.
